# RAGStudio 后端开发规范

## 一、总则

### 1.1 目的
统一团队编码风格和质量标准，确保代码可读性、可维护性和系统稳定性。

### 1.2 适用范围
本规范适用于RAGStudio后端所有Java模块，包括framework、infra-ai、bootstrap、common等。

### 1.3 技术栈
- **语言**：Java 17（LTS）
- **框架**：Spring Boot 3.5
- **构建工具**：Maven 3.9+
- **数据库**：PostgreSQL 16 + pgvector
- **缓存**：Redis 7 + Redisson
- **消息队列**：RocketMQ 5.x

## 二、代码风格

### 2.1 命名规范

| 元素 | 规范 | 示例 |
|------|------|------|
| 包名 | 全小写，点分隔 | `com.byteq.ai.ragstudio.rag.core.agent` |
| 类名 | UpperCamelCase | `AgentLoop`, `ReActResponseParser` |
| 接口名 | UpperCamelCase，不加 I 前缀 | `ModelProtocol`, `ChatClient` |
| 方法名 | lowerCamelCase | `executeAgentLoop()`, `buildRequestBody()` |
| 常量 | UPPER_SNAKE_CASE | `MAX_ITERATIONS`, `DEFAULT_TIMEOUT_SECONDS` |
| 变量 | lowerCamelCase | `llmResponse`, `toolRegistry` |
| 枚举 | UpperCamelCase | `TraceStatus`, `ChunkType` |

### 2.2 文件结构规范

```java
// 文件头部顺序
1. package 声明
2. import（按字母排序，静态导入放最后）
3. 类 Javadoc
4. 类注解（@Slf4j, @Service, @Component 等）
5. 类声明

// 类内部顺序
1. 静态常量
2. 实例字段
3. 构造函数（通过 @RequiredArgsConstructor 或手动写）
4. 公共方法
5. 私有方法
6. 内部类/接口
```

### 2.3 代码格式

| 规则 | 设置 |
|------|------|
| 缩进 | 4个空格（不使用Tab） |
| 行宽 | 120字符 |
| 大括号 | K&R风格（左括号不换行） |
| 空行 | 方法间1行，逻辑块间1行 |
| 空格 | 操作符两侧、逗号后、关键字后加空格 |

```java

 * 方法的简短描述。
```

### 3.3 注释原则
- 公共API必须写Javadoc

- 注释写"为什么"而不是"是什么"

## 四、异常处理规范

### 4.1 异常分类

| 类型 | 用途 | 示例 |
|------|------|------|
| `BusinessException` | 业务逻辑异常，可预期 | 参数校验失败、权限不足 |
| `SystemException` | 系统级异常 | 数据库连接失败、外部服务调用失败 |
| `IllegalArgumentException` | 非法参数 | 空值校验、范围校验 |
| `IllegalStateException` | 状态异常 | 对象状态不允许当前操作 |

### 4.2 异常处理原则

```java
// GOOD: 具体异常类型，有业务含义
throw new BusinessException(ErrorCode.KB_NOT_FOUND, kbId);

// GOOD: 包装后重新抛出，附带上下文信息
try {
    externalService.call();
} catch (IOException e) {
    throw new SystemException("调用外部服务失败: " + url, e);
}

// BAD: 吞掉异常
try { ... } catch (Exception e) {}

// BAD: 只打印不处理
try { ... } catch (Exception e) { e.printStackTrace(); }

// BAD: 捕获过宽的异常类型
try { ... } catch (Exception e) { ... }
```

### 4.3 日志规范

```java
// 使用 Lombok @Slf4j，不使用 System.out.println

// 各日志级别使用场景
log.error("严重错误，需要告警", e);
log.warn("潜在问题，需要关注");
log.info("关键业务流程节点");
log.debug("开发调试信息");

// 日志中使用占位符，不拼接字符串
log.info("Agent 迭代 {}/{} - 消息数: {}", iteration, maxIterations, msgCount);

// BAD
log.info("Agent 迭代 " + iteration + " - 消息数: " + msgCount);
```

## 五、安全规范

### 5.1 SQL注入防护
- 所有数据库操作使用MyBatis-Plus参数化查询
- 禁止拼接SQL字符串
- 动态排序字段使用白名单校验

### 5.2 敏感信息保护
- API Key / Password 不能在日志中输出
- 使用 `@JsonIgnore` 或自定义序列化器屏蔽敏感字段
- 配置文件中的敏感信息使用环境变量或配置中心

### 5.3 输入校验

```java
// Controller 层使用 @Valid 注解
@PostMapping
public Result<Void> create(@Valid @RequestBody CreateRequest request) { ... }

// Service 层使用 Assert 或 Preconditions
Assert.notNull(knowledgeBase, "知识库不存在");
Assert.isTrue(StrUtil.isNotBlank(name), "名称不能为空");
```

## 六、性能规范

### 6.1 数据库操作
- 批量操作使用 `saveBatch()`，单次批大小 ≤ 500
- 查询使用索引，定期检查慢查询日志
- 大结果集使用分页查询
- 避免在循环中进行DB操作

### 6.2 缓存使用
```java
// 使用 Redisson 分布式缓存
RBucket<AiModelConfigCache> bucket = redissonClient.getBucket(cacheKey);
AiModelConfigCache cached = bucket.get();

// 缓存穿透保护：缓存空值
if (cached == null) {
    cached = loadFromDB();
    bucket.set(cached, 5, TimeUnit.MINUTES); // 设置TTL
}
```

### 6.3 并发控制
- 使用 `ConcurrentHashMap` 而不是 `HashMap` + synchronized
- 线程池使用 `ThreadPoolExecutor` 而非 `Executors.newCachedThreadPool()`
- 限流使用 `Semaphore` 或 Redisson RateLimiter

## 七、测试规范

### 7.1 测试分层

| 层级 | 覆盖要求 | 工具 |
|------|---------|------|
| 单元测试 | 核心Service/Util ≥ 80% | JUnit 5 + Mockito |
| 集成测试 | 关键业务流程 | Spring Boot Test + Testcontainers |
| API测试 | 全部REST端点 | llm-eval.sh（scripts/llm-eval.sh，含知识库检索质量评估） |

## 八、Git 工作流

### 8.1 分支策略

| 分支 | 用途 | 合并规则 |
|------|------|---------|
| `main` | 生产环境代码 | 仅从 release / hotfix 合并 |
| `develop` | 开发主线 | 从 feature 合并，需Code Review |
| `feature/*` | 新功能开发 | 合并到develop，需通过CI |
| `release/*` | 发布准备 | 合并到main + develop |
| `hotfix/*` | 紧急修复 | 合并到main + develop |

### 8.2 提交信息规范

```
<type>(<scope>): <subject>

<body>

<footer>
```

| type | 说明 |
|------|------|
| feat | 新功能 |
| fix | Bug修复 |
| refactor | 重构 |
| docs | 文档 |
| test | 测试 |
| chore | 构建/工具 |

示例：
```
feat(rag): 新增多通道并行检索引擎
fix(agent): 修复Agent循环中Action误识别死循环
refactor(embedding): 统一EmbeddingService接口
```
